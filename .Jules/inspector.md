## 2025-05-04 - Fix i18n text matching in design system tests
**Learning:** UI strings have been abstracted into localization dictionaries (`locale/en.json`). Tests asserting on text content (like checking for the '§' symbol or checking title case) should parse and search these JSON strings, not raw Python source code (`_read_app_source()`).
**Action:** When updating tests that assert on UI copy, use `locale/en.json` as the source of truth for text instead of attempting to scan for hardcoded string literals in the source.
## 2025-05-04 - AppTest st.html Extraction and Sync Executemany Assertions
**Learning:** Streamlit's `AppTest` does not populate `at.markdown` with raw HTML content injected via `st.html()`. Instead, `st.html()` content must be extracted by filtering the relevant container (e.g., `at.main`) for `type(el).__name__ == 'UnknownElement'` and `el.type == 'html'` and accessing `el.proto.body`. Also, when mocking asynchronous futures with empty data structures (like `lineage_data = []`), any logic guarded by `if data:` will bypass `executemany` statements. Tests counting total database execution calls must dynamically adjust expected call counts if intermediate data processing steps are intentionally short-circuited via mocks.
**Action:** When writing or updating assertions on raw HTML in tests, traverse the target `AppTest` container to find and extract `UnknownElement(html)` nodes rather than relying solely on `at.markdown`. When validating database integration logic in asynchronous contexts, ensure expected query execution counts accurately reflect bypassed logic loops caused by mock behavior.
