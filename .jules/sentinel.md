## 2025-05-02 - Missing HTML Escaping in Streamlit Markdown Blocks
**Vulnerability:** Cross-Site Scripting (XSS) vulnerability was found in the `app.py`'s `render_glossary` function. Specifically, dynamic variables like glossary `term_row["term"]`, `term_row["definition"]`, `term_row["calculation"]`, `term_row["domain"]`, and `term_row["steward"]` were interpolated directly into a multi-line `st.markdown(..., unsafe_allow_html=True)` block without prior HTML sanitization.
**Learning:** `unsafe_allow_html=True` allows direct rendering of HTML strings to enable complex layout styles, but it makes any unescaped string injection highly vulnerable to XSS if those values can be tampered with or contain unescaped entities (e.g. from user input or databases). Although `_DEMO_GLOSSARY` currently acts as the source, the mechanism presents a risk for future enhancements relying on external sources.
**Prevention:** Always use `html.escape()` around any dynamic string variables that are being interpolated into an `st.markdown(..., unsafe_allow_html=True)` call.

## 2025-05-05 - SQL Injection Vulnerability via Unescaped Identifiers
**Vulnerability:** A critical SQL Injection vulnerability was identified in `src/sync/push.py`'s `_push_to_databricks` function. When executing dynamic DDL operations like `ALTER TABLE` and `COMMENT ON TABLE`, unescaped identifier strings (table names, schema names, and catalog names) resulting from splitting the `table_full_name` were formatted directly into the SQL query strings. While single quotes for text values were correctly replaced (`.replace("'", "''")`), backticks for the identifiers themselves were not replaced, making it possible for attackers to break out of backticks and inject arbitrary SQL if they manage to provide a manipulated table or column name.
**Learning:** DDL operations do not support standard SQL parameterization, which necessitates constructing raw strings. Using `f"`{p}`"` for identifiers is only safe if `p` has been sanitized. Unsanitized variable injection into DDL query string exposes the system to severe SQL injection attacks.
**Prevention:** Always manually escape identifiers in SQL constructs when query parameterization is unavailable. When targeting Databricks or Spark SQL environments, ensure backticks in identifiers are securely doubled (`replace("\`", "\`\`")`) prior to formatting into the target string.
