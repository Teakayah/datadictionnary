When a user clicks on a node in `vis-network`:

```javascript
    if (params.nodes.length > 0) {
        var nodeId = params.nodes[0];
        window.parent.postMessage({
            type: "streamlit:setComponentValue", // Wait, is there a way to pass data without custom component wrapper?

```

Streamlit allows component to pass messages back if it's `streamlit:setComponentValue`, but for `components.html` it's generally one-way unless you use `window.parent.postMessage({type: 'streamlit:setQueryParams', queryParams: {expand: nodeId}}, '*')`.
Wait, `streamlit:setQueryParams` doesn't work if the app is not listening. Streamlit does listen to it! Let's check `streamlit` source.
Streamlit intercepts `streamlit:setQueryParams` from any iframe? Wait, no. Streamlit 1.30+ uses a different protocol, and passing query params might not be allowed.
What if we use `window.parent.location.assign(window.parent.location.pathname + "?tab=search&expand=" + encodeURIComponent(nodeId))`? It will refresh the Streamlit page. Will `st.session_state` be maintained? NO, session state is cleared on full page reload unless backed by cookies/url.

How to implement the callback without page refresh?
We can use Streamlit's `st.components.v1.components.declare_component` to create a tiny bridge component, OR use a hidden `st.query_params` update, OR we can just use `window.parent.postMessage({type: 'streamlit:setComponentValue', ...})`. But `declare_component` requires files.

Is there a simpler way?
`window.parent.postMessage({type: "streamlit:setComponentValue", value: nodeId}, "*")` works IF the iframe is a Streamlit component. `st.components.v1.html` is exactly that, BUT it does not register a component callback.
